# Domain docs

## Layout and reading rules

This repository uses a single-context layout:

- `GLOSSARY.md` at the repository root: read before exploring.
- `docs/adr/`: read decisions relevant to the area being explored.

If these files are absent, proceed silently. The domain-modeling skill
creates them when terms or decisions are resolved.

## Vocabulary

Use glossary terms when naming domain concepts in issues, proposals,
hypotheses, and tests. Follow any explicitly preferred terminology.

If a concept is missing, reconsider whether it belongs in the project's
vocabulary or note the gap for domain-modeling.

## Decisions

Explicitly surface any proposal that contradicts an existing ADR.
Identify the ADR and explain why the decision should be reconsidered.
